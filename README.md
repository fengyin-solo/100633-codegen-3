# 城市地下综合管廊运行维护管理平台

面向管廊主体台账、入廊管线登记、廊内环境监测、通风排水消防、结构沉降与渗漏处置、巡检检修与隐患整改、入廊作业审批和运维值班的一体化城市地下综合管廊运行维护管理工作台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `urban-utility-tunnel:entries` 这一项，或调用 `resetModule(模块)`。

## 保洁作业单台账（文件进出 + 跨入口对账）

业务规则集中在 `frontend/src/api/cleaning-service.ts` 与 `frontend/src/data/cleaning.ts`，
页面（`views/cleaning/`）只负责上传/下载与展示，不在组件里做判断。

- **进出各一个口子**：上传口为「保洁作业单台账」页的「导入车单文件」，只收 CSV，
  表头须为 `车次编号,清运日期,保洁区域,保洁班组,清运量(车)`，日期 `YYYY-MM-DD`；
  下载口为月底「按区域归总并另存」后的「下载另存文件」（`保洁作业月度归总-YYYY-MM.csv`）。
- **逐行核对与废行**：保洁区域、保洁班组不在字典、日期格式不对、清运量缺失或非数字、车次缺失的行不进台账，
  原样另记到「废行簿」并写清缘由；表头缺列或空文件按**整批回退**处理，一行都不入。
- **同车次覆盖不叠加**：以车次编号为唯一键，重复导入按新批次覆盖旧版（含同批文件内重复车次，后到行覆盖）。
- **对账挂待核**：清运量与巡检任务当天、同区域（巡检路线）上报的「发现问题数」之和比对。
  阈值按口径版本区分（见下），超阈值或（现行口径下）当天无巡检上报可对的作业单先挂「待核」，
  由监管员在「廊内巡检任务」页下方的「保洁对账待核」面板核定，核定后冻结，同车次再导入不翻案（可在巡检侧撤销核定）。
- **月底归总另存**：按清运月份 × 保洁区域汇总清运量与单数（已入账/待核分列），
  另存为快照；页面列表与下载文件取同一份快照存储，之后台账再变动不回改旧快照（仅提示可重新另存）。
- **存量回填**：首次打开时对没有口径版本的存量作业单以**完工日期**为轴回填一次并冻结。
- **交接清单**：导入批次、整批回退、并发回退、待核核定、月度归总、存量回填的结论都写入
  `cleaningHandover` 存储，「保洁作业单台账-交接清单/口径」与「运维值班交接」页下方展示同一份；台账动作与清单结论同一次提交落库。
- **并发仲裁**：同一时刻只允许一笔导入入账（服务层互斥锁），后到者整笔回退并在交接清单留痕。

### 口径版本（改版口径只对新记录生效，既有记录按当时口径保留原判）

| 版本 | 适用期间（按完工日期） | 对账阈值 | 残缺取值补齐 |
| --- | --- | --- | --- |
| v1-纸质车单口径 | 2023-12-31 及以前 | 不对账 | 清运量残缺按 **1 车/单** 补录，保留原判 |
| v2-联单口径 | 2024-01-01 ~ 2025-12-31 | 差异 > 50% | 以当天同区域巡检遗留问题数补齐，无巡检则按 1 车并保留原判 |
| v3-车单电子化口径 | 2026-01-01 起（现行） | 差异 > 30%，无巡检上报也挂待核 | 无外部车单可凭的暂补 1 车并挂待核，待监管员核定 |

差异 = `|清运量 − 遗留问题数| / max(两者)`。

### 冲突仲裁规则及依据

1. 外部车单文件优先于群消息与手工登记：车单是清运现场带车次编号的原始凭证；
2. 同一车次编号以后到的导入批次为准并覆盖，不叠加；
3. 监管员核定结论优先于系统自动判定，核定后冻结（除非监管员在巡检侧撤销核定）；
4. 同刻并发提交只让先到者拿锁入账，后到者整笔回退；
5. 月底归总以已另存快照为准，页面与下载同源，快照不随后续台账变动漂移。
